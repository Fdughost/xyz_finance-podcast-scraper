# 播客监控与日报系统

一个自动化的泛财经播客数据监控系统，定期抓取小宇宙上的播客数据并生成Excel日报，重点覆盖公募基金公司官方播客及优质财经节目。

## 功能特性

- 🎯 **自动爬取**: 定期抓取39个播客节目的最新数据
- 📊 **数据统计**: 订阅数、播放量、互动指标等关键数据
- 📈 **Excel报表**: 自动生成格式化的日报，按订阅数降序排列
- 🗄️ **数据存储**: 本地SQLite数据库存储历史数据
- 🔄 **增量更新**: 支持与昨日数据对比分析

## 环境要求

- Python 3.12+
- 依赖包见 `requirements.txt`

## 安装使用

1. 克隆仓库
```bash
git clone https://github.com/Fdughost/daily-podcast-news.git
cd daily-podcast-news
```

2. 安装依赖
```bash
pip install -r requirements.txt
```

3. 运行监控
```bash
python main.py
```

## 输出文件

- **Excel报表**: `reports/播客监控日报_YYYY-MM-DD.xlsx`
- **日志文件**: `logs/main.log`, `logs/crawler.log`
- **数据库**: `data/podcast_monitor.db`

## 配置说明

`config.json` 主要配置项：

- `podcasts`: 播客列表配置，每条记录包含：
  - `name`: 播客名称
  - `podcast_id`: 小宇宙播客 ID（24位十六进制，可留空由爬虫自动解析）
  - `category`: 分类，可选 `公募基金` / `其他金融机构` / `独立节目`
  - `institution_name`: 机构或主理人名称
  - `enabled`: 是否启用
- `crawler_settings`: 爬虫设置（请求延迟、重试次数等）
- `report_settings`: 报表设置（输出目录、是否包含图表等）

## 日报下载

静态页面与 Next.js 页面均可免登录下载日报。点击顶部“下载日报”，在月历中选择已有日报的日期，再点击“确认下载”。没有报表的日期不可选，默认选中最新一期。文件仍由现有 GitHub 报表地址提供。

两套页面共用 `web/public/report-download.js`。修改组件后运行 `python3 generate_html.py`，将相同组件内嵌到静态页面。新增日报会通过现有生成流程进入日期清单，无需配置云端数据库或 Supabase 环境变量。

### 下载流程验收

使用 Python 3.12 或更新版本，先安装 `requirements-dev.txt`，并运行 `python3 -m playwright install chromium`。在两个终端分别启动：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

```bash
cd web
npm ci
npm run build
npm run start -- --hostname 127.0.0.1 --port 8766
```

在项目根目录运行：

```bash
python3 -m unittest discover -s tests -v
```

若使用已安装的 Chrome，可设置 `PLAYWRIGHT_CHANNEL=chrome`。浏览器测试会真实下载最新及最早的日报，验证 Excel 结构并与本地文件比较内容；因此需要访问 GitHub。生成流程测试仅在临时目录写入数据，不运行爬虫。

发布时需要将 Next.js 界面代码同步到实际部署分支；每日任务只同步数据文件，不会自动同步界面改动。Supabase 云端项目清理须在上线验证及必要数据备份后进行。


## 静态版订阅趋势

趋势总览覆盖最新日报中的全部节目，默认展示近30天的小图、订阅数、净增人数和增长率。支持节目或机构搜索、分类筛选、近7／30／60天切换，以及按增长率、净增人数或订阅规模排序。

可以一键对比增长前5、规模前5或整个筛选结果，也可勾选少量节目比较。对比图支持增长率与订阅人数切换；总览小图各用独立纵轴。日期按日历对齐，缺失数据不补零、不跨缺口连线。

界面源文件在 `static_assets/trends.html`、`trends.css` 和 `trends.js`。运行 `python3 generate_html.py` 会将其内嵌到静态页面，现有每日任务无需额外构建。Next.js 趋势组件保持原有实现。

### 节目改名与历史身份识别

节目以小宇宙 `podcast_id` 为稳定标识（节目 URL 中的 ID），名称仅用于显示。SQLite 已按 `(podcast_id, crawl_date)` 唯一保存快照；Excel 新增 `节目ID` 列，网页增量、趋势序列及选择状态均使用 ID。

旧版 Excel 没有 ID 时，`podcast_identity.py` 从数据库快照的 `podcast_name`、原始 `title` / `config_name` 及配置建立精确名称到 ID 的映射，优先匹配报表当日快照。不做模糊匹配；存在多个候选 ID 时中止生成并要求补充报表 ID，防止误合并同名节目。完全未知的旧名称暂保留独立的 `legacy-name:` 标识。生成历史网页时应保留 `data/podcast_monitor.db`。历史报表和快照中的原名称保持原样。

已核验：`65d541dcc10c027a33679998` 在 2026-10-10 的快照名称为“燕妮聊基金”，2026-10-11 起为“燕妮小录”。同一个 ID 的历史数据会自动衔接；无需为改名新建节目或修改旧订阅数。


## 静态版订阅排行

排行默认展示最新日报的全部节目，支持节目或机构搜索、分类筛选、订阅数正序或倒序，以及前10／20名快捷查看。筛选保留全局名次，同订阅数采用并列名次；前10／20名始终取筛选范围内订阅数最高的节目。

标准条形按真实订阅数等比例显示；对数比例用于观察规模较小的节目，并明确提示条长不代表人数倍数。所有数字都直接展示，缺失值不当作零。界面位于 `static_assets/ranking.html`、`ranking.css` 和 `ranking.js`，由现有生成器内嵌，无需新增依赖。
